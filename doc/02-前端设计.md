## 1. 设计目标

- **灵动简约**：暖色、留白、圆角柔和、克制的动效。
- **信息密集但不拥挤**：排班是高密度信息，靠分组、层级和色彩状态让人一眼读懂。
- **手机优先**：玩家主要在手机（含微信/QQ 内置浏览器）查看排班和报名。
- **可换肤**：所有视觉值来自设计令牌，换主色或风格只改一处。

## 4. 设计令牌

当前视觉变量定义在 `app/globals.css` 的 `:root` 中。正式组件化时继续以 CSS 自定义属性作为设计令牌来源，避免组件各自定义互相冲突的色值。

### 4.1 颜色（浅色）

```css
:root {
  --bg:        #FAF8F3;  /* 页面背景，暖白 */
  --surface:   #FFFFFF;  /* 卡片、抽屉 */
  --sunk:      #F3F0E8;  /* 泳道底、分段控件底 */
  --line:      #E7E2D6;  /* 边框、分割线 */
  --text:      #2A2723;  /* 正文 */
  --muted:     #7C766A;  /* 次要文字 */

  --accent:      #2F5D62; /* 主色：青黛 */
  --accent-soft: #E3EDEC;

  --ok:      #4C7A56;  --ok-bg:   #E8F0E6;   /* 已满员 */
  --warn:    #A9782A;  --warn-bg: #F6EDD9;   /* 还缺人 */
  --bad:     #A8493C;  --bad-bg:  #F6E3DF;   /* 缺坦克/治疗、危险操作 */

  --shadow: 0 1px 2px rgba(60,50,30,.05), 0 8px 24px rgba(60,50,30,.07);
}
```

### 4.2 颜色（深色）

```css
:root[data-theme="dark"] {
  --bg:#1D1B18; --surface:#272420; --sunk:#221F1B; --line:#3A362F;
  --text:#EDE9DF; --muted:#9A9488;
  --accent:#7FB3B3; --accent-soft:#2A3A3A;
  --ok:#8DBB92; --ok-bg:#2A3529;
  --warn:#D9AE63; --warn-bg:#3A3122;
  --bad:#E08A7C; --bad-bg:#402723;
  --shadow: 0 8px 24px rgba(0,0,0,.4);
}
/* 同时在 @media (prefers-color-scheme: dark) 下对 :root:not([data-theme="light"]) 重复一份，实现"跟随系统" */
```

深色模式使用暖调深灰，不用纯黑；从项目第一天起就用变量，后期补会很痛苦。

### 4.3 成员文字标识色板

成员文字标识显示名字首字，底色按用户 ID 哈希取自下列色板（白字，需对比度 ≥ 4.5:1）；百业标识按百业 ID 生成，不需要图片数据：

`#2F5D62 #8A6A3D #6B5B8C #A05A4A #4C7A56 #5B7699 #8C5B73`

### 4.4 字体

| 用途 | 字体栈 |
|---|---|
| 标题 | `"Noto Serif SC", "Songti SC", serif`，字重 600 |
| 正文 | `-apple-system, "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif` |

- 衬线体**只用于标题**，并做子集化（只含常用字），控制体积。
- 正文用系统字体，保证首屏速度。
- 中文行高：正文 1.5，长文 1.7。

字号阶梯：

| Token | 大小 | 用途 |
|---|---|---|
| `text-xs` | 12px | 状态标签、辅助信息 |
| `text-sm` | 13–14px | 正文、卡片内容 |
| `text-base` | 15–16px | 表单、长文 |
| `text-xl` | 20–22px | 页面标题、抽屉标题 |
| `text-2xl` | 28px | 首页主标题 |

### 4.5 形状、间距、动效

| 项 | 值 |
|---|---|
| 圆角 | 小 8px（标签内元素）／中 12px（场次卡片、输入框）／大 16px（泳道、面板）／抽屉 20px／按钮、胶囊 999px |
| 间距刻度 | 4 / 8 / 12 / 16 / 20 / 24 / 32 / 48 |
| 边框 | 1px `--line`，层级主要靠边框和底色，阴影非常轻 |
| 动效时长 | 150–280ms |
| 缓动 | 悬停等用 `ease`；抽屉用 `cubic-bezier(.2,.8,.2,1)` |
| 减弱动效 | 尊重 `prefers-reduced-motion`，直接关闭过渡 |

**动效只用于回应用户操作或状态变化**（悬停抬起 2px、抽屉滑入、进度变化），不做进入页面时的装饰动画。

### 5.1 基础组件（正式组件化建议）

当前演示尚未采用 shadcn/ui；后续可按需使用 Radix 等无障碍基础能力，不要求整体迁移组件库。

Button（主要／次要／幽灵／危险）、IconButton、Input、Textarea、Select、Checkbox、Switch、SegmentedControl（分段切换）、Dialog、Sheet（抽屉，桌面右侧、手机底部）、Tooltip、Toast、Skeleton、EmptyState、MemberBadge、MemberBadgeStack、Badge、Tabs。

## 6. 副本板块设计（核心）

### 6.1 周泳道（已确认）

- 周一至周日各是一条**竖向泳道**，横向并排；默认固定七天，容器根据可用宽度平均分配七条泳道宽度，不额外按内容扩张。
- 桌面端优先让七条泳道在内容区域内平均分配；当可用宽度不足以满足单条泳道最小可读宽度时，容器横向滚动。移动端（≤720px）将周一至周日纵向排列，每天的场次列表放在日期标题下方，取消横向滚动；每日高度随内容变化，空日期保留简短提示。
- 泳道底色 `--sunk`，圆角 16px，内边距 10px，最小高度 560px，今天用 1.5px 主色描边。
- 表头：左侧周几，右侧日期，下方 1px 分割线。
- 桌面框架不设整体最大宽度，侧栏宽 200px；周历内容不设 1180px 上限，左右内边距 24px。单日泳道最小宽度 156px，定位文字不换行，成员文字标识保留独立空间；空间不足时仅周历容器横向滚动。
- 同一泳道内场次按开始时间升序排列。
- 空泳道提示："这天没有安排副本"，管理员可见"开一场"入口。

### 6.2 场次卡片 `EventCard`

```
┌──────────────────────────┐
│ 20:00 · 我已报名          │  ← 时间；本人已参加时附注，左侧 3px 主色条
│ 副本一                    │  ← 副本名，加粗
│ 承伤  ◉                   │
│ 奶妈  ◉ ◉                 │  ← 成员文字标识 + 虚线空位
│ 输出  ◉ ◉ ◉ ◉ ◉ ◉ ◉      │
│ [ 10/10 已满员 ]          │  ← 状态胶囊
└──────────────────────────┘
```

状态规则（`stat(event)`）：

| 条件 | 状态 | 色 |
|---|---|---|
| 已排人数 ≥ 总需求 | 已满员 | `--ok` |
| 承伤或奶妈不足 | 缺承伤／缺奶妈 | `--bad` |
| 其余未满 | 缺 N 人 | `--warn` |

其他规则：

- 卡片整体是一个按钮，悬停上移 2px 并出现阴影，点击打开详情抽屉。
- 场次标题由创建者自定义，与副本名称分开保存；卡片以场次标题为主标题，并同时展示副本名称，详情抽屉也分别标注两者。
- 已取消的场次置灰并加删除线标题；草稿场次显示"草稿"角标（仅管理员可见）。
- 最多 10 人团，成员文字标识直接放在卡片里即可，无需折叠。
- 成员文字标识的显示顺序：定位内按排班顺序。

### 6.3 周切换与数据

- 顶部：标题（百业名 · 副本周历）、副标题（日期范围 + 北京时间）、`WeekSwitcher`、视图切换（周日历／成员矩阵）、管理员的"开一场"按钮。周切换只出现在副本周历中，可查看历史周；我的本周固定展示当前自然周，不提供周切换。
- 数据来源：`GET /guilds/:id/events?week=` 一次取整周，key 为 `['events', guildId, weekKey]`。
- 切周时预取相邻周。
- 周视图按北京时间（Asia/Shanghai）的自然周展示，周一 00:00 至下周一 00:00；以周接口返回的周起止、ISO `weekKey` 与时区为准。前端周切换与 C# 后端采用同一组跨年及北京时间周边界验证样例，不直接共享运行时代码。

### 6.4 场次详情抽屉 `EventDrawer`

- 桌面：右侧滑出；手机：底部弹出，最高 85% 屏高。点击遮罩或按 Esc 关闭。
- 内容自上而下：标题 + 时间 + 状态 → 已参加角色详情（角色名、鹅力、流派、场次定位）→ 队伍需求（承伤 / 奶妈 / 输出的已占位数、总名额和空位）→ 选择角色与场次定位 → 报名；管理员额外提供指派入口。
- 成员操作：
  - 普通成员：选择本人具体游戏角色和场次定位后"报名这场"；报名即确认占位，已报名或候补时仅提供"取消报名"，不提供再次确认或请假操作。
  - 管理员/社长：可指派任意本百业成员，包含其他管理员及社长，或取消其排班；角色管理/移出权限保持原边界。指派满员提示“该定位已满，请选择其他定位或等待空位”，不自动转候补；请求用 action=assign，本人开放报名用 action=signup。
  - 换角色/定位：先取消再重新报名/指派。取消确认说明“原名额和候补顺序不保留，重新报名可能候补或失败”；取消成功刷新名单，再选择角色/定位提交新请求。不提供直接编辑报名入口。
  - 提醒开关与提前分钟数继承百业配置，可在开始前调整，一期没有渠道选择。
  - 场次开始后：隐藏普通报名、指派、修改和取消入口，场次及排班只读；退会/移出/解散/注销仍可随时执行并清理关联数据，已开始场次不递补。实际出勤为二期。
  - 默认队伍：2 奶妈、1 承伤、7 输出；同定位候补按报名顺序自动递补，以该账号当前默认角色占位并通知。
  - 角色选择器预选成员账号的默认角色，允许本场选择其他角色；未手动设置默认角色时预选最早创建的角色。
- 异常反馈（Toast）：
  - 时间冲突："时间冲突：{名字}同时已在「{副本}」"
  - 定位已满："{定位}位已满，已加入候补队列"
  - 取消后："已取消报名"
- 乐观更新：报名/取消先更新界面，失败回滚并提示；账号冲突跨角色检查，首尾相接的场次不冲突。

### 6.5 成员矩阵（二期）

### 6.6 我的本周（一期）

- 手机端主入口，固定当前北京时间自然周，纵向列表按时间排序，只显示"我"的场次，不提供修改周次的操作。

## 7. 其他页面要点

### 7.1 玩家广场 `/players`

- 玩家广场仅展示未加入任何百业的玩家；加入百业后从广场列表移除，不提供“只看散人”开关。
- 顶部筛选条：区服、流派、在线时段。
- 卡片默认展示：玩家名（游戏角色名）、鹅力、多选流派，不提供资料隐藏开关。

### 7.2 百业主页 `/guilds/[id]`

- 头部：百业文字标识、名称、区服、招募状态胶囊、成员数。
- 内容区：简介、招募要求、成员列表（角色名、鹅力、流派默认公开，无隐藏开关）、近期副本概览（公开版本，不含详细名单）。
- 操作区：未登录用户进入登录流程；已登录且未加入百业的用户可申请加入；成员进入"本周副本"。

### 7.3 成员管理

- 成员管理页提供“审批申请”“成员管理”“参与情况”三个页签。
- 参与情况显示“本周已排班次数”“本周未排班成员”和“累计已排班排名”。本周及累计都计 confirmed，候补/取消不计；累计从当前加入时间截至当前周结束，包含本周未开始安排，不计未来周，退会重入重新累计，不称实际出勤。
- 统计列表分页，名次由服务端在分页前计算；“仅未排班”筛选使用 unassigned_only，不能只在当前页本地过滤后宣称是全百业未排班名单。
- 列表：文字标识、名字、角色、加入时间；定位和近 4 周出勤率属于二期成员统计，不放入一期主流程。
- 管理员可审批申请、生成邀请链接、移出成员；社长额外可在成员管理列表中设置或取消管理员身份。
- 危险操作（移出、转让、解散）统一使用确认对话框，按钮用 `--bad`。
- 退会、移出、解散任何时候可执行；确认说明硬删除历史与未来记录，若目标创建过模板/场次/邀请，关联场次及其他人的排班也会删除。社长未转让退会必须显示“退会即解散整个百业，删除所有百业业务数据”，要求单独确认。普通成员/管理员离开后转 /guilds，相关缓存失效；其他成员所在百业被删除后重新读 /me，关闭旧抽屉。

### 7.4 个人设置 `/settings`

- 个人资料中的区服类型只有“官服”和“渠道服”两个选项；不使用具体游戏大区名称作为区服类型。
- 个人资料：昵称、默认游戏角色和只读已绑定邮箱；不在设置页提供改邮箱、邮件开关或渠道偏好。
- 角色列表中，默认角色显示“默认”标记，其他角色提供“设为默认”操作；一个账号只有一个默认角色，切换后不改变已有正式排班。
- 角色选择器未手动设置默认角色时，预选最早创建的角色。

### 7.4.1 我的申请 `/settings/applications`

- 从个人设置进入，展示百业名称、申请时间、状态（待处理/通过/拒绝/已撤回），按状态筛选、分页。
- pending 才显示“撤回”；确认后调用 POST withdraw，按钮请求期间禁用，成功刷新记录；申请同时被处理时按接口实际状态提示，不能直接本地删行假装撤回成功。
- 百业解散或本人相关记录已被删除后，不保留历史卡片；空列表提示“暂无申请记录”，提供百业列表入口。加入百业后仍可撤回其他旧 pending 申请，不能新申请第二个百业。

### 7.4.2 收到的邀请 `/settings/invitations`

- 列表展示百业、邀请时间、有效期和当前状态，点击进入独立定向邀请页。通知 invitation.received 使用同一详情路由。
- 默认展示 pending，允许查看已处理状态；相关百业/本人关联记录删除后同步移除。设置页只提供入口，不把完整列表塞入资料表单。

### 7.4.3 注销 `/settings/account-deletion`

- 展示“注销将删除账号、邮箱/QQ 关联、角色和全部关联业务记录”；社长未转让时额外醒目标明“同时解散百业，删除全体成员在该百业的数据，其他成员账号/个人角色保留”。
- 输入 DELETE，二次确认后 POST /me/account-deletion，携带当前 Bearer 与 CSRF。请求期间禁用重复提交，不乐观宣称删除成功。
- 成功后停止 SignalR/重试/轮询，清除 Token 与所有账号缓存，通知其他标签页停止连接，返回 /login。QQ 待绑定页也提供注销入口，不强制先验证邮箱；注销不发送邮件。

### 7.4.4 独立邀请预览

- `/invitations/code/[code]` 从链接进入，通过 GET /invitations/code/{code} 预览安全百业摘要、有效期/剩余次数和可用状态；未登录先登录，QQ 未绑定先绑定，完成后回到平台内同一路由，不在 return_to 携带 Token。
- `/invitations/[id]` 通过 GET /invitations/{invitation_id} 读取本人定向邀请。展示百业资料摘要、邀请方可公开昵称、状态/有效期及接受/拒绝按钮，不暴露邮箱或内部名单。
- 已属于百业的账号禁用加入/接受，展示当前归属；定向邀请仍可拒绝。过期、撤销、用尽、已处理分别说明原因，资源硬删除/无权访问时显示“邀请不存在或已失效”。
- 接受成功刷新 /me、成员与设置邀请列表，跳转对应百业；拒绝成功刷新邀请及通知查询。写操作返回竞态错误时重新预览，不凭初次预览保证可加入。
- 邀请码路径在日志/分析/错误上报中脱敏，页面禁用向外发送完整地址，使用 Referrer-Policy=no-referrer。

### 7.5 站内通知中心

接口、消息结构、未读与已读处理见 [《04-通知与提醒方案》第 6 节](./04-通知与提醒方案.md)。共享已读布尔值与固定消息列表替换为真实记录，一期所有业务消息只在站内展示。

- 通知列表：未读主色圆点，点击跳转到对应场次/页面并标记已读。
- 每个标签页在已登录且完成邮箱绑定后建立一个 `/hubs/notifications` 连接，接收 `notifications.changed`（reason 为 created/read/deleted）并使通知列表/角标查询缓存失效；deleted 另重读 /me 和当前百业上下文。角标以 REST 返回为准，不按实时提示次数累加；其他标签页已读同样触发刷新。
- 首次连接、重连、网络恢复及页面重新聚焦后补查列表与未读数。连接正常不固定轮询，断线/初次连接失败时每 30 秒降级查询，不可见时暂停；重连成功补查后停止轮询。退出/切换账号停止旧连接、重试和轮询，清理旧缓存，迟到结果核对账号。
- 移除站内/邮件渠道开关，站内中心默认启用。百业/场次只配置开打提醒开关与提前分钟数，不影响审批等即时通知；QQ/微信和免打扰仍不纳入一期。

## 9. 状态管理与数据流（后端接入目标）

- **服务端数据**：全部交给 TanStack Query，不复制到全局 store。
- **真实接口替换**：账号、角色、百业、报名/取消、指派、审批、设置和通知全部调用 `/api/v1` 接口；演示数据、身份开关及仅展示成功提示的模拟写入退出正式业务流程。
- **UI 状态**（当前视图、抽屉开合）：本地组件状态或 URL 参数。副本周历当前周可保存在 URL（`?week=2026-W42&view=week`）；我的本周固定当前自然周，不接受 `week` 参数。管理员身份来自服务端，演示用身份切换不得进入正式版本。
- **乐观更新**：报名、取消、指派使用 `onMutate` 更新缓存，`onError` 回滚，`onSettled` 使缓存失效。
- **刷新策略**：窗口重新聚焦、网络恢复时重新请求；一期排班页可加 30 秒轮询，通知使用 SignalR 提示 + REST 补查与断线降级，不扩展排班实时广播。
- **请求封装**：业务请求携带 `Authorization: Bearer ...`；401 先合并执行一次刷新，成功后最多重放一次被认证拒绝的请求，仍失败则清理账号缓存并跳登录。403 提示无权限，409 展示冲突业务码对应文案。网络错误、503 提供重试，不当作登录失效；非幂等写操作发生网络超时时不自动重试。
- **首次绑定限制**：403 / EMAIL_BINDING_REQUIRED 转 `/bind-email`，不进入刷新循环；读取 `/me.requires_email_binding` 后才初始化业务查询，绑定完成重新读取 /me。本人注销为白名单，不初始化其他业务查询。
- **硬删除反馈**：404 清理对应资源缓存并关闭详情；退会/解散后重新读取 /me，清理旧百业查询；SignalR notifications.changed 的 reason=deleted 时刷新通知并重读上下文，旧业务不能继续留在界面中。注销后其他标签页停止旧连接，旧请求/迟到响应不得恢复缓存。

### 9.1 登录与 Token 管理

- 邮箱注册先通过 `/auth/email-registration/code` 发送验证码，再调用 `/auth/register` 提交 email/password/challenge_id/verification_code；邮箱密码登录使用 `/auth/login`，不发送验证码。
- QQ 回调后恢复会话并读取 /me，未绑定邮箱转 `/bind-email`；通过 `/auth/email-binding/code` 和 `/auth/email-binding` 完成验证，绑定页不能跳过。绑定不强制设置密码，QQ 账号继续 QQ 登录，不能将已注册邮箱自动合并为另一个账号。
- 注册/登录表单不将密码、验证码写本地存储或 URL。发送失败提示重试/冷却，不展示注册或绑定成功；已有邮箱冲突明确提示。
- CSRF 凭证按当前认证身份获取，登录身份切换后在相应表单请求前重新获取，避免沿用匿名或其他账号的 Antiforgery 凭证。

- QQ OAuth 回调由后端处理，设置 Refresh Token Cookie 后跳回前端允许地址，不通过 URL 传递凭证。
- Access Token 只保存在浏览器内存，默认有效期 15 分钟；Refresh Token 为随机字符串，由后端写入 HttpOnly、Secure、SameSite=Lax Cookie，会话默认绝对有效期 7 天。两种凭证均不写入 localStorage 或 sessionStorage。
- SignalR 的 accessTokenFactory 读取当前内存 Access Token；浏览器 WebSocket/SSE 连接可能由 SDK 将 access_token 放入查询参数，仅 `/hubs/notifications` 允许此例外，必须 HTTPS/WSS 且代理/应用/追踪屏蔽该参数。普通业务 URL 和页面跳转禁止 Token，Refresh Token 不进入 Hub。
- Hub 在认证 Token 到期时关闭连接，前端复用统一刷新协调器取得新 Token 后重连，不能仅更新内存而保留旧连接。初次 start 失败也需退避重试；自动重连采用有上限退避，失败期间保留降级轮询，401/403 进入统一认证处理，不无限重试。
- 初次 QQ 授权返回及页面重载时先获取 CSRF、refresh、/me；邮箱注册/密码登录成功直接持有 Access Token 再读 /me。确认无需绑定后才初始化业务查询，恢复前不发业务请求。
- 刷新与退出请求携带 Cookie，并通过 `X-CSRF-TOKEN` 发送请求凭证，后端检查 Origin 与 Antiforgery 凭证；一次刷新轮换一次 Refresh Token。统一认证请求入口协调同页及多标签页刷新，防止并发使用旧凭证触发重放撤销；刷新请求自身的 401 不进入递归刷新。
- 退出调用 `POST /api/v1/auth/logout` 撤销服务端刷新会话，成功后清除内存凭证与用户查询缓存。默认旧 Access Token 到期前仍可能有效，不在 UI 中宣称已立即撤销所有访问凭证。
- 前端隐藏按钮依据 `/me` 和成员接口的当前角色，不从 JWT 推导百业管理权限；最终权限由后端校验。
- `/login` 为邮箱/密码与 QQ 入口；`/register` 包含邮箱、验证码、密码及可选昵称，发送按钮按 resend_after 冷却；绑定页只要求邮箱/验证码。字段边界与错误依《一期接口契约》，失败保留安全表单输入，密码/验证码不进入日志或持久缓存。
- 一期不提供忘记密码、绑定后改邮箱或业务邮件设置入口，邮件只用于注册和 QQ 首次邮箱绑定验证。

## 10. 权限在前端的处理

- 登录后获取 `me` 和当前百业的 `membership.role`，放入上下文。
- `lib/permissions.ts` 暴露 `can(action, ctx)`，例如 `can('event.create')`、`can('member.remove', target)`。
- `RoleGate` 和按钮禁用只是**体验优化**；所有写操作后端必须再次校验，403 时前端要有清晰提示。
- 原型里的"管理员模式"开关**仅用于演示**，正式版本中角色来自接口，不提供手动切换。

## 11. 文案与空状态

原则：用用户的语言，主动语态，句式简短，不道歉也不卖萌，告诉用户下一步做什么。

| 场景 | 文案示例 |
|---|---|
| 空泳道 | 这天没有安排副本 |
| 空周（管理员） | 这周还没有安排副本，来开一场吧 |
| 空周（成员） | 这周还没有安排副本，管理员排好后会通知你 |
| 无搜索结果 | 没有找到符合条件的玩家，试试放宽区服或定位 |
| 请求失败 | 加载失败，请检查网络后重试 [重试] |
| 无权限 | 你没有这个操作的权限，请联系管理员 |
| 冲突 | 时间冲突：{名字}同时已在「{副本}」 |
| 定位满 | {定位}位已满，已加入候补队列 |

加载使用**骨架屏**而不是转圈；骨架形态与最终布局一致（泳道 + 卡片轮廓）。

## 12. 无障碍与质量标准

- 对比度：正文 ≥ 4.5:1，状态色同时配文字，不仅靠颜色区分。
- 所有交互元素可键盘操作，焦点样式为 2px 主色描边；抽屉打开时锁定焦点，Esc 关闭，关闭后焦点回到触发元素。
- 抽屉、对话框使用 Radix 的 Dialog，自带 ARIA。
- 可交互的成员文字标识、图标按钮提供 `aria-label`。
- 尊重 `prefers-reduced-motion` 和 `prefers-color-scheme`。
- 状态变化（报名成功、冲突）用 `role="status"` 的 Toast 播报。

## 14. 工程约定（正式工程化时采用）

- TypeScript `strict`；禁止 `any`，确需使用须注释原因。
- 组件文件 PascalCase，hooks 以 `use` 开头，工具函数 camelCase。
- 请求、响应及业务枚举（定位、状态、角色）的契约由后端 OpenAPI 定义，生成至 `packages/api-client`，组件统一引用生成类型，禁止手改生成文件或在组件里散落魔法字符串。前端表单校验与 C# 后端 DTO 校验分别实现。
- 样式以 CSS 自定义属性令牌为准；后续若引入 Tailwind 或 `cva`，需先确认依赖并与现有 CSS 令牌对齐。
- 提交规范：Conventional Commits；PR 前通过 lint、类型检查、单元测试。
- 关键 E2E：邮箱验证码注册/密码登录、QQ 首次建号与强制绑定、重载仍绑定受限、验证码过期/用途隔离、邮箱冲突、刷新/退出、百业及报名/候补/开始后锁定。验证所有业务动作不触发邮件，注册/首次绑定才调用验证服务；权限和并发使用真实后端集成检查。
- 实时通知 E2E：在线新通知更新、本人隔离、断线降级/重连补查、JWT 到期刷新重连、多标签页已读同步、退出/切换账号不显示旧数据；覆盖手机和内置浏览器的传输回退。
- 删除/页面 E2E：当前周累计截止、申请记录撤回竞态、邀请码/定向预览及处理、任意时间退出/解散/注销、社长退会即解散、所有关联记录消失、其他账号/角色不误删、旧链接和迟到查询不恢复数据。
- 页面底部固定声明："非官方玩家工具，与游戏运营方无关"。
