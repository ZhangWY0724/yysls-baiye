# 部署说明（Docker + Caddy，同域名）

架构：浏览器 → Caddy（HTTPS）→ `/` 前端（3000）、`/api/v1/*` 与 `/hubs/*` API（5080）；API、前端与 PostgreSQL / Redis 在同一个 compose（`docker/compose.server.yml`）里，API 通过服务名 `postgres`、`redis` 访问数据库。

## 一次性准备
1. 域名解析到服务器，Caddy 能申请证书（开放 80/443）。
2. 数据库迁移已执行（本机开发和服务器共用同一个库时已执行过）。
3. 在服务器仓库目录创建 `docker/.env`（复制 `docker/.env.example`，**不要提交**），至少填写：
   - `POSTGRES_PASSWORD`、`REDIS_PASSWORD`：与现有实例一致。
   - `JWT_SIGNING_KEY`：新生成的随机值，例如 `openssl rand -base64 48`。
   - `RESEND_API_KEY`、`EMAIL_FROM`：发信凭证与发件人。
   - `PUBLIC_HOST`（如 `yy.example.com`）、`PUBLIC_ORIGIN`（如 `https://yy.example.com`）。
   - `REDIS_KEY_PREFIX`：与本机开发共用同一个 Redis 时必须与开发不同（默认 `yanyun:prod:`）。
   - `PROXY_IP`：compose 网络网关地址，见下文。
4. 把 `docker/Caddyfile.example` 的内容合并进 Caddy 配置，替换域名后重载。

## 启动与更新
postgres、redis 的定义保持不变，已运行的容器不会被重建，只会新建 api、web：
```bash
docker compose -f docker/compose.server.yml --env-file docker/.env up -d --build api web
docker compose -f docker/compose.server.yml logs -f api
```
更新：`git pull` 后重新执行上面的命令。有新迁移时，**先执行迁移再重启 API**。

## 获取 PROXY_IP
Caddy 在宿主机上，经 `127.0.0.1:5080` 访问 API，API 看到的来源是 compose 网络的网关。首次执行 `docker compose ... up -d` 时网络会被创建（postgres、redis 已在运行时网络已存在），查看网关：
```bash
docker network inspect yanyun-infrastructure_default -f '{{(index .IPAM.Config 0).Gateway}}'
```
把结果填进 `docker/.env` 的 `PROXY_IP`，再执行启动命令。未正确配置时，API 看不到真实客户端 IP 与 HTTPS 协议（限流、日志会按网关地址计算）。

## 验证
- `curl -s http://127.0.0.1:5080/health/ready` 应返回健康。
- 浏览器打开域名：注册收到邮件、登录、创建百业、排班、通知实时到达。
- 用两个账号验证 SignalR（申请入会被通过后，对方无需刷新即可看到百业入口）。

## 注意
- 5432、6379 映射到了所有网卡；如果本机开发需要远程连接，请用防火墙只放行你的 IP，不要对公网开放。
- `data-protection` 数据卷必须保留，丢失后已加密的邀请链接无法找回，CSRF Cookie 也会失效一次。
- 本文件对应的容器构建与运行尚未在真实服务器上验证。
