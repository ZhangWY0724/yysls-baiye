# 部署说明（Docker + Caddy，同域名）

架构：浏览器 → Caddy（HTTPS）→ `/` 前端（3000）、`/api/v1/*` 与 `/hubs/*` API（5080）；API 连接服务器上已运行的 PostgreSQL / Redis。

## 一次性准备
1. 域名解析到服务器，Caddy 能申请证书（开放 80/443）。
2. PostgreSQL / Redis 已运行（`docker/compose.server.yml`），数据库迁移已执行。
3. 在服务器仓库目录创建 `docker/.env`（复制 `docker/.env.example`，**不要提交**），至少填写：
   - `POSTGRES_PASSWORD`、`REDIS_PASSWORD`：与现有实例一致。
   - `JWT_SIGNING_KEY`：新生成的随机值，例如 `openssl rand -base64 48`。
   - `RESEND_API_KEY`、`EMAIL_FROM`：发信凭证与发件人。
   - `PUBLIC_HOST`（如 `yy.example.com`）、`PUBLIC_ORIGIN`（如 `https://yy.example.com`）。
   - 与本机开发共用同一个 Redis 时，`REDIS_KEY_PREFIX` 请保持与开发不同（默认 `yanyun:prod:`）。
4. 把 `docker/Caddyfile.example` 的内容合并进 Caddy 配置，替换域名后重载。

## 启动与更新
```bash
docker compose -f docker/compose.prod.yml --env-file docker/.env up -d --build
docker compose -f docker/compose.prod.yml logs -f api
```
更新：`git pull` 后重新执行上面的 `up -d --build`。有新迁移时，**先执行迁移再重启 API**。

## 验证
- `curl -s http://127.0.0.1:5080/health/ready` 应返回健康。
- 浏览器打开域名：注册收到邮件、登录、创建百业、排班、通知实时到达。
- 用两个账号验证 SignalR（申请入会被通过后，对方无需刷新即可看到百业入口）。

## 注意
- `docker/compose.server.yml` 把 5432、6379 映射到了所有网卡；如果本机开发需要远程连接，请用防火墙只放行你的 IP，不要对公网开放。
- `data-protection` 数据卷必须保留，丢失后已加密的邀请链接无法找回，CSRF Cookie 也会失效一次。
- API 通过固定网段 `172.28.0.0/24` 的网关 `172.28.0.1` 信任 Caddy 转发的 `X-Forwarded-*`；若该网段与服务器现有网络冲突，请同时修改 `compose.prod.yml` 里的网段和 `Proxy__KnownProxies__0`。
- 本文件对应的容器构建与运行尚未在真实服务器上验证。
