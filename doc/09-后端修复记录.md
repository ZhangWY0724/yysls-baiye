# 后端修复记录

日期：2026-10-13。保持 API 服务停止，通过 TestServer 验证；不新增或执行正式 public schema 迁移，不发送真实邮件。经用户确认，基础设施测试创建独立随机 test_* schema，使用独立 Redis 前缀；测试 schema 保留。

## 认证一致性

- 注册先验证验证码，不立即消费。账号写入在数据库事务中完成，Redis 会话创建成功后提交；保存或会话创建失败回滚账号，正确验证码仍可重试。邮箱唯一约束阻止重复账号。
- 成功提交后的验证码清理失败仅记录不含秘密的日志，不把已成功注册返回成失败。数据库提交失败时尽力撤销预建会话。PostgreSQL/Redis 仍不构成分布式事务；提交结果未知时，可通过邮箱密码登录恢复，不应盲目创建新账号。
- 刷新先验证会话、读取账号状态、生成 JWT，再原子轮换 Redis 令牌。数据库故障或请求取消不提前轮换。
- 轮换后的旧令牌允许固定 10 秒重试，返回相同刷新令牌且不延长窗口；窗口外重放仍撤销会话族。恢复令牌通过 Data Protection 加密，部署需保留密钥目录，多实例必须共享密钥。

## 通知与查询

- HTTP 提交后只把变更提示放入容量 2048 的队列，后台独立作用域批量检查账号并发送 SignalR，不持有业务 advisory lock。每批最多 100 个提示，整批 2 秒超时；队列满时丢弃旧提示，正文与未读状态仍由数据库持久化并可通过 REST 补查。
- Outbox 和提醒任务批量读取账号、百业、场次、成员和去重记录；提醒每轮最多 100 场，下一轮继续处理。任务失败丢弃未提交提示、清空跟踪状态。
- 玩家、成员、百业、申请、邀请、周历按当前页批量加载关联数据；我的本周使用关联查询；参与排名按统计分布一次查询计算，保持同次数同排名。
- 一期继续使用业务事务全局 advisory lock 保障容量及硬删除一致性；取消或锁获取失败时释放事务。是否细化锁需根据压测决定。

## 幂等与错误

- 现有必填幂等接口保持规则，其他业务写操作显式携带 Idempotency-Key 时也会持久化响应；同标识不同内容返回冲突。前端角色、模板、邀请、申请创建自动携带标识，失败重试复用。
- OpenAPI 增加可选幂等头说明。EF 保存异常包装的 PostgreSQL 故障返回统一 503，不暴露内部连接信息。
